# Testing Workflow

ParkTwin AI has two independent test surfaces: the Python backend
(`pytest`) and the TypeScript frontend (`tsc` / `next lint` / `next build`).

## Backend (`pytest`)

```bash
pytest -q                 # full suite
pytest tests/unit         # unit only
pytest tests/integration  # integration only
pytest -k "occupancy"     # by name filter
```

Covers:

- Configuration loading and the settings model.
- Shared validators and plate formatting (OCR fusion).
- Database layer (SQLite) — tables, CRUD, sessions.
- The full API surface (every router, mounted prefixes, forbidden routes absent).
- The analytics and reporting engines.
- **Architecture-ownership regression** — `tests/unit/test_architecture_ownership.py`
  (11 tests) guaranteeing Module 2 is the sole owner of parking-slot assignment
  (G1–G5) and that dependency directions hold.

Notes:

- `test_parktwin.db` is **regenerated by the suite on each run** (gitignored) — it
  reappears after the run; that is expected.
- `asyncio_mode = "auto"` is configured in `pyproject.toml`; async tests need no
  explicit marker.
- The suite must stay green before any PR is merged.

## Frontend (`apps/web`)

```bash
cd apps/web
npm run typecheck   # tsc --noEmit (strict, noUncheckedIndexedAccess)
npm run lint        # next lint
npm run build       # next build
```

All three gates must pass. There is no `next test` harness configured; type,
lint, and build provide the frontend quality gates.

## Architecture-ownership regression

`tests/unit/test_architecture_ownership.py` statically + functionally guarantees:

- `TrackManager` (M1) exposes **no** slot-ownership surface.
- No production path writes slot ownership to a record.
- M1↔M2 stay decoupled; M4/M5 never import M1.
- Snapshot annotation consults M2 before any M1 fallback.
- `IntegrationService.handle_frame` returns Module-2-owned vehicles.

If you touch slot assignment, the integration event bus, or M1↔M2 coupling,
extend this suite.

## Pre-PR checklist

- [ ] `pytest -q` green (full suite, including ownership regression).
- [ ] `npm run typecheck && npm run lint && npm run build` green (in `apps/web`).
- [ ] New code has tests; existing tests still pass.
- [ ] No new duplicate implementation without a Change Log entry (see
      [`PROJECT_MEMORY.md` §13](../../PROJECT_MEMORY.md#13-change-log)).
- [ ] `PROJECT_MEMORY.md` updated for any new/moved module, service, model, or endpoint.
- [ ] No `TODO`/`FIXME`/stale markers left in source.
