# PROBLEM STATEMENT
### The <span class="highlight-cyan">Parking Intelligence Gap</span>

> **“How can we transform raw parking-lot video into structured, real-time parking intelligence?”**

### The 5 Operational Questions We Must Answer:
1. **WHO?** Which vehicle is entering? *(Identity & Plate OCR)*
2. **WHERE?** Where is the vehicle within the facility? *(Spatial tracking)*
3. **WHICH SPACE?** Which parking space is available or occupied? *(Slot allocation)*
4. **WHAT STATE?** Is the vehicle entering, parked, moving, or exiting? *(State machine)*
5. **WHAT ACTION?** Should the system guide, alert, or update the operator? *(Dispatch)*

# EXISTING CHALLENGES
### Why Traditional Parking Monitoring Is Insufficient

* **01 — Passive CCTV**: Continuous visual streams, but zero inherent structured parking state.
* **02 — Fragmented Information**: Gate ANPR, loop detectors, and signage operate in disconnected silos.
* **03 — Manual Monitoring**: Security staff suffer cognitive fatigue watching multiple raw camera feeds.
* **04 — No Spatial Intelligence**: Detections lack geometric coordinates relative to physical bays.
* **05 — Limited Driver Assistance**: Drivers must blindly circle aisles hunting for vacant spots.
* **06 — No Unified Operational Model**: Missing the complete physical-to-virtual chain:
  $$\mathbf{Vehicle \longrightarrow Camera \longrightarrow Location \longrightarrow Bay \longrightarrow Event \longrightarrow User}$$

> **Core Design Principle:** Connect vehicle intelligence with spatial intelligence.

# PARKTWIN METHODOLOGY
### Perception $\longrightarrow$ Event $\longrightarrow$ Action

* **STEP 1 — Camera Ingestion**: Consumes CCTV, RTSP/ONVIF IP cameras, and recorded video.
* **STEP 2 — Computer Vision Engine**:
  * **YOLOv8** for real-time vehicle detection and classification.
  * **ByteTrack** for robust multi-object tracking across frames.
  * **PaddleOCR** for license-plate identity extraction (ANPR).
* **STEP 3 — Event Generation**:
  * Emits typed JSON event records (Vehicle ID, Plate, Camera ID, Timestamp, Vector, Confidence).
  * **The event is the foundational unit of truth** across the platform.

# SOLUTION ARCHITECTURE
### From Events to Parking Intelligence

$$\mathbf{Cameras \rightarrow Vision\ Engine \rightarrow Telemetry\ Layer \rightarrow Intelligence\ Engine \rightarrow Digital\ Twin \rightarrow UI}$$

* **Decoupled Architecture**: Vision inference never parses UI elements; frontend never parses raw video frames.
* **Parking Intelligence Engine**: Maintains vehicle state, bay occupancy, reservation links, and violation logic.
* **The Digital Twin**: Canonical facility geometry (bays, aisles, ramps, coordinates).
* **Dual Experience**:
  * **Operator Dashboard**: Facility-wide telemetry, 3D replica, and analytics.
  * **Driver Dashboard**: Parking discovery and in-facility turn-by-turn guidance.

# END-TO-END SOLUTION
### The 8-Stage Closed-Loop Vehicle Journey

1. **01 — ENTRY**: Vehicle approaches facility entrance gate barrier.
2. **02 — IDENTIFICATION**: Camera detects vehicle and ANPR extracts plate.
3. **03 — STATE CREATION**: System emits structured vehicle telemetry event.
4. **04 — PARKING DECISION**: Associates reserved space (`SP-24`) or assigns dynamic bay.
5. **05 — NAVIGATION**: Digital Twin generates in-facility turn-by-turn routing.
6. **06 — PARKING**: Vehicle reaches bay; slot state transitions to **OCCUPIED**.
7. **07 — MONITORING**: Live duration counter tracks active parking session.
8. **08 — EXIT**: Camera detects egress; session is closed and bay is liberated.

# REQUIREMENTS TO COMPLETE THE PROJECT
### What Is Required for Full-Scale Completion?

* **01 — Camera Infrastructure**: RTSP/ONVIF IP cameras covering entry, exit, drive aisles, and bay angles.
* **02 — Compute Infrastructure**: Dedicated GPU edge/inference server (VRAM-optimized for parallel streams).
* **03 — Facility Data**: Verified architectural floor plans, $(X,Y)$ bay coordinates, lane geometry, and ramp connections.
* **04 — Data & AI**: Larger representative local plate dataset; weather/night-glare validation.
* **05 — Software & Integration**: Production backend, event queue, barrier access control, and user auth.
* **06 — Field Validation**: Live multi-vehicle stress testing, occlusion resilience, and end-to-end latency audits.

> **“Full completion requires combining that software foundation with real-world infrastructure, data, and field validation.”**
